# 电商AI视频客服系统 - 操作指南

> **v4.0 · 全栈 AI Agent + 真实推理链路** — 通过 117 项测试，覆盖 LangGraph / Multi-Agent / LangSmith / LiteLLM / Ollama（qwen2.5:3b 本地生成 + nomic-embed-text 混合语义检索）/ FastAPI / Next.js

## 1. 系统概述

本系统是基于 **LiveKit Agents + LangChain + LangGraph + Multi-Agent + FastAPI + Next.js** 构建的电商AI视频客服平台，提供实时视频对话、智能商品检索、订单管理、退换货处理等全流程客服能力。

### 技术架构

| 组件 | 技术选型 | 说明 |
|------|----------|------|
| 实时通信 | LiveKit | WebRTC 音视频基础设施 |
| 语音识别 | Deepgram Nova-3 | 实时语音转文字 |
| 大语言模型 | Ollama qwen2.5:3b（本地真实调用）/ OpenAI GPT-4o（路由降级） | 对话理解与生成 |
| 语音合成 | Cartesia Sonic-3 | 文字转语音 |
| 数字人 | Lemonslice | AI视频形象生成 |
| RAG框架 | LangChain | 知识检索增强生成 |
| 向量数据库 | ChromaDB + nomic-embed-text | 商品知识存储（768维真实向量 + 中文关键词混合检索） |
| **流程编排** | **LangGraph StateGraph** | **意图路由 + 条件边 + 多Agent调度** |
| **多Agent协作** | **Supervisor 模式** | **ProductAgent / OrderAgent / SupportAgent** |
| **可观测性** | **LangSmith** | **全链路 Tracing / Golden Eval / Cost 追踪** |
| **模型路由** | **LiteLLM + Ollama** | **复杂度分级路由 / 本地模型零成本降级** |
| **后端API** | **FastAPI** | **7个REST端点 / Pydantic校验 / CORS** |
| **前端** | **Next.js 14** | **React 聊天界面 / 指标面板 / API代理** |

## 6. 生产就绪保障层 (P0)

系统内置 **6大生产保障模块**，确保服务在真实生产环境中稳定运行：

![生产保障概览](screenshots/00-overview-v2.png)

### 6.1 熔断降级

![熔断降级演示](screenshots/07-circuit-breaker.png)

**问题**：LLM 服务（OpenAI）不可用时，系统会持续报错，用户无法获得响应。

**方案**：实现熔断器状态机（CLOSED → OPEN → HALF_OPEN → CLOSED）+ 模型降级链（GPT-4o → GPT-4o-mini）。

| 状态 | 行为 | 触发条件 |
|------|------|----------|
| **CLOSED** | 正常请求 GPT-4o | 连续失败 < 5 次 |
| **OPEN** | 直接降级到 GPT-4o-mini | 连续失败 ≥ 5 次 |
| **HALF_OPEN** | 试探性请求 GPT-4o | 冷却期结束（30s） |
| **CLOSED** | 恢复正常 | 试探请求成功 |

**关键参数**：
- 失败阈值：5 次连续失败
- 冷却时间：30 秒
- 降级链：GPT-4o → GPT-4o-mini → 预设回复

### 6.2 限流防护

![限流防护演示](screenshots/08-rate-limit.png)

**问题**：恶意用户或异常流量可能导致 API 费用暴增、服务过载。

**方案**：Token Bucket 算法，每用户每分钟最多 60 次请求。

| 指标 | 值 | 说明 |
|------|-----|------|
| 令牌桶容量 | 60 | 每分钟最大请求数 |
| 填充速率 | 1 令牌/秒 | 匀速补充 |
| 超限行为 | 返回 429 | Too Many Requests |
| 持续超限 | IP 加入黑名单 | 连续 3 次超限 |

### 6.3 安全检测

![安全检测演示](screenshots/09-security.png)

**问题**：用户可能在对话中发送手机号、身份证号、银行卡号等敏感信息，直接存储存在泄露风险。

**方案**：正则检测 + AES-GCM 加密存储 + 日志脱敏。

| 检测类型 | 正则模式 | 脱敏示例 |
|----------|----------|----------|
| 手机号 | 11位数字，1开头 | `13812345678` → `138****5678` |
| 身份证号 | 18位，末位可为X | `310101199001011234` → `310101****1234` |
| 银行卡号 | 16-19位数字 | `6222021234567890123` → `6222****0123` |

**加密方案**：AES-256-GCM，敏感字段加密后存储，密钥通过环境变量注入。

### 6.4 监控面板

![监控面板演示](screenshots/10-monitoring.png)

**问题**：生产环境缺乏可观测性，问题发现滞后。

**方案**：实时指标采集 + 告警规则引擎。

**核心指标**：

| 指标 | 类型 | 说明 |
|------|------|------|
| 请求总量 | Counter | 累计请求数 |
| 错误率 | Gauge | 错误请求占比 |
| P95 延迟 | Histogram | 95分位响应时间 |
| 活跃会话 | Gauge | 当前在线会话数 |

**告警规则**：

| 规则 | 阈值 | 级别 |
|------|------|------|
| 错误率过高 | > 5% | WARNING |
| P95 延迟过高 | > 8s | WARNING |
| 日成本超预算 | > 80% | CRITICAL |

### 6.5 备份恢复

![备份恢复演示](screenshots/11-backup.png)

**问题**：ChromaDB 向量数据库数据丢失将导致商品知识全部丢失。

**方案**：定时全量备份 + 会话归档 + 完整性校验。

| 步骤 | 说明 |
|------|------|
| 全量备份 | ChromaDB → SQLite 备份文件 |
| 向量索引备份 | 备份所有 collection 的向量数据 |
| 完整性校验 | SHA-256 checksum 验证 |
| 会话归档 | 会话数据归档为 JSONL 格式 |
| 过期清理 | 保留最近 7 天，自动删除过期备份 |

### 6.6 健康检查

![健康检查演示](screenshots/12-health-check.png)

**问题**：外部服务（OpenAI、Deepgram 等）不可用时无法及时发现。

**方案**：每 30 秒探测所有外部服务健康状态。

| 服务 | 探测方式 | 超时 |

| ChromaDB | 本地心跳 | 2s |

| Lemonslice | API 连通性 | 5s |

### 7.1 LangGraph 流程编排

![LangGraph 流程编排](screenshots/14-langgraph.png)

**能力**：基于 LangGraph StateGraph 的意图路由工作流。

**工作流**：
```
START → Router(意图分类) → [ProductAgent | OrderAgent | SupportAgent] → Response → END
```

**意图分类**：关键词评分机制，覆盖 3 类意图 + UNKNOWN 兜底。

| 意图 | 关键词示例 | 路由目标 |
|------|-----------|----------|
| PRODUCT | 商品、价格、库存、推荐、多少钱 | ProductAgent |
| ORDER | 订单、物流、快递、退货、退款 | OrderAgent |
| SUPPORT | 你好、帮助、怎么、投诉、人工 | SupportAgent |
| UNKNOWN | 无匹配关键词 | Response（兜底回复） |

**演示操作**：点击「🔀 LangGraph」按钮，观察对话流中的路由路径和条件边执行日志。

### 7.7 v4.0 真实推理链路（本地 LLM + 混合语义检索 + 电商联动）

以上 7.1–7.6 为控制台场景模拟；v4.0 起 `/api/chat` 全链路为**真实调用**，无任何硬编码回复：

| 环节 | 实现 | 说明 |
|------|------|------|
| 语义检索 | ChromaDB + `nomic-embed-text`（768维真实向量，68商品） | 文档/查询分别加 `search_document:` / `search_query:` 前缀 |
| 混合排序 | `_hybrid_merge`：关键词优先 + RRF 融合 | 中文字面命中走精确关键词；改述句（如"能自动翻译外语的设备"）由向量召回 |
| 回复生成 | Ollama 本地 `qwen2.5:3b` | 检索结果注入上下文，LLM 基于真实商品数据作答 |
| 商品卡片 | 京东/拼多多搜索直达链接 | 按价格升序，最低价绿色「最低」角标，点击新标签页跳转 |
| 工具标记 | `tools_used` 如实上报 | 仅在实际调用时标记 `rag_search` / `ollama_chat`，不造假 |
| 降级保障 | Ollama 不可用 → 关键词检索 + 意图识别兜底 | 兜底回复引用用户原问题，绝不答非所问 |
